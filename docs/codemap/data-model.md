# Data model

There is no database, ORM or migration directory; the census lists no schemas. The plugin's
state is a handful of local files, JSON payloads exchanged with Claude Code, and GitHub
labels and comments used as shared coordination state. Each entry names who writes it and
who reads it.

## Local state under `.foundry/`

`.foundry/` is gitignored in this repo as local Foundry state (`.gitignore`), and the
`loop-report` skill describes it as local observability, never a committed baseline
(`plugins/foundry/skills/loop-report/SKILL.md`).

- **`.foundry/telemetry.jsonl`** - one JSON object per verb run. Written by
  `foundry-verb-wrap`, which lives in the separate Foundry repo, not here
  (`plugins/foundry/skills/loop-report/SKILL.md`). Read by
  `plugins/foundry/scripts/foundry-loop-report#load`, which skips blank lines and torn
  (undecodable) lines and returns `None` when the file is missing. Fields it reads:
  `verb`, `ms` (sort key), `duration_ms`, `exit`, `ts`, `scope`, `placement`, `rules`
  (`plugins/foundry/scripts/foundry-loop-report#tally`,
  `plugins/foundry/scripts/foundry-loop-report#summarise`), and `smells`, a map of smell
  name to count, where a map containing `incomplete-run` marks a partial scan
  (`plugins/foundry/scripts/foundry-loop-report#smell_trend`). The path defaults to
  `$FOUNDRY_TELEMETRY`, then `.foundry/telemetry.jsonl`
  (`plugins/foundry/scripts/foundry-loop-report#main`). The MCP `gate_status` tool reads
  it through the same script, resolving the path from the repo's mise env
  (`plugins/foundry/scripts/explain-mcp/foundry.mjs#runLoopReport`).
- **Loop-report JSON summary** - `--json` output: `{telemetry, verbs, red, thrash}`, with
  per-verb `runs`, `fails`, `regress` and `last`; a missing log prints
  `{"telemetry": null}` (`plugins/foundry/scripts/foundry-loop-report#as_json`,
  `plugins/foundry/scripts/foundry-loop-report#main`). Consumed by
  `plugins/foundry/scripts/explain-mcp/tools.mjs#gateStatus`.
- **`.foundry/pr-url`** - the URL of the PR just opened or updated, one line. Written by
  `plugins/foundry/scripts/foundry-ship-pr` at the repo top level.
- **`.foundry/pr-watch.log`** - stdout and stderr of the detached CI watch, ending with
  the line `---PR-CI-WATCH-DONE--- exit <n>`. Written by
  `plugins/foundry/scripts/foundry-ship-pr#watch_detached` when not in a Herdr pane; the
  `ship` skill polls it for the sentinel (`plugins/foundry/skills/ship/SKILL.md`).

## Tool-generated baselines (consumer repos)

- **`.habit-hooks/snooze.json`** and **`eslint-suppressions.json`** - committed
  suppression baselines in a consumer repo, regenerated only by tools
  (`habit-sensors --all | habit-snooze --prune`, `eslint --prune-suppressions`).
  `snooze.json` is a flat list of file paths, whole-file granular
  (`plugins/foundry/skills/repo-align/SKILL.md`). This plugin never writes either one:
  `plugins/foundry/hooks/guard-generated-files.sh` denies an Edit, Write or MultiEdit
  whose `file_path` ends in either name, and a Bash command that writes one through a
  redirect, `tee`, `cp`, `mv`, `install`, `rsync`, `sed -i` or `of=`
  (`plugins/foundry/hooks/guard-generated-files.sh#writes`,
  `plugins/foundry/hooks/guard-generated-files.sh#deny_snooze`,
  `plugins/foundry/hooks/guard-generated-files.sh#deny_eslint`). The rule that baselines
  only shrink is stated in `CONTRACT.md`.
- **`.habit-hooks/`** - its presence at the repo root or one directory down opts a
  package into the Stop-hook smell check (`plugins/foundry/hooks/habit-hooks-guard.sh`).
- **`.gitleaks.toml`** - consumer-repo allowlist (`[allowlist] paths`) that the
  `foundry-secret` skill adds narrow entries to for confirmed false positives
  (`plugins/foundry/skills/foundry-secret/SKILL.md`).

## Plugin install state

- **`${CLAUDE_PLUGIN_DATA}/.installed.json`** - a copy of the `package.json` the npm tree
  was built from, written only after `npm ci` succeeds; the hook compares it with the
  plugin's `package.json` to decide whether to reinstall. `package.json` and
  `package-lock.json` are copied into the same directory first
  (`plugins/foundry/hooks/mcp-deps.sh`).
- **`plugins/foundry/package.json`** - declares the MCP server's runtime dependencies,
  `@modelcontextprotocol/sdk` and `zod`, with `version` `1.0.0`, which the MCP server
  reports as its own version (`plugins/foundry/scripts/explain-mcp/tools.mjs#createServer`).
- **`plugins/foundry/scripts/jev/vendor/jev-core/package.json`** - records the vendored
  `@cmaintz/jev-core` version; generated by
  `plugins/foundry/scripts/jev/vendor-jev-core.sh`.

## Git-side state

- **`<git dir>/foundry-claim`** - the session nonce of a ticket claim, written into the
  worktree's own git dir by the `feature` skill (`plugins/foundry/skills/feature/SKILL.md`).
- **`<git common dir>/info/exclude`** - `plugins/foundry/hooks/habit-hooks-guard.sh`
  appends `.claude/worktrees/` when that directory exists and is not already ignored.
- **`tickets/<slug>.md`** - fallback ticket file the `spec` skill writes when `gh` or a
  GitHub remote is unavailable, and a ticket source `feature` reads
  (`plugins/foundry/skills/spec/SKILL.md`, `plugins/foundry/skills/feature/SKILL.md`).

## GitHub labels and comments as state

- **Ticket lifecycle labels** `agent:ready` -> `agent:working` -> `agent:blocked` (or back
  to `agent:ready`). `spec` files an issue with `agent:ready` and assigns the owner;
  `feature` claims by adding `agent:working`, removing `agent:ready` and the assignee;
  escalation sets `agent:blocked` and reassigns; stale claims (inactive over 2 hours)
  return to `agent:ready` (`plugins/foundry/skills/spec/SKILL.md`,
  `plugins/foundry/skills/feature/SKILL.md`). `repo-align` uses the same labels plus
  `align` for its target issues (`plugins/foundry/skills/repo-align/SKILL.md`).
- **Claim marker comment** - `claimed by feat/<slug>-<n> at ../_wt/<slug>-<n> session
  <nonce>`; the latest such comment owns the ticket (`plugins/foundry/skills/feature/SKILL.md`).
- **Issue form** `agent-feature` with sections Intent, Acceptance criteria, Definition of
  Done, Scope boundaries, Pointers (`plugins/foundry/skills/spec/SKILL.md`).
- **Governance labels** `ruleset-change` and `suppression` - a human's sign-off; an agent
  Bash call that applies, aliases or (re)defines either is denied by
  `plugins/foundry/hooks/guard-governance-labels.sh`.
- **PR draft/ready state** - `foundry-ship-pr` opens PRs ready for review
  (`plugins/foundry/scripts/foundry-ship-pr#create_pr`) and marks a reused draft ready
  (`plugins/foundry/scripts/foundry-ship-pr`); `foundry-pr-watch --ready-on-green` marks a
  deliberate draft ready when the verdict is green (`plugins/foundry/scripts/foundry-pr-watch`).

## Docs and hook payload formats

- **`docs/codemap/` files** - YAML frontmatter `sha`, `slice`, `kind` (`domain`, `lens`,
  `index`) and, for domain slices, `paths`; backticked path or path-plus-symbol citations;
  a closing `## Unknowns` (`plugins/foundry/skills/codemap/FORMAT.md`). Written only by
  the `codemap` skill after verification and committed through `ship`
  (`plugins/foundry/skills/codemap/SKILL.md`); read by `feature`, `spec` and `review`
  (`plugins/foundry/skills/feature/SKILL.md`, `plugins/foundry/skills/spec/SKILL.md`,
  `plugins/foundry/skills/review/SKILL.md`).
- **Census JSON** - `manifests`, `entrypoints`, `schemas`, `envVars`, churn, co-change,
  `slicePlan`, `unsliced`, printed by
  `plugins/foundry/scripts/codemap/census.mjs#census`; shape documented in
  `plugins/foundry/scripts/codemap/README.md`.
- **Claude Code hook payloads** - the hooks extract `tool_name`, `tool_input.file_path`,
  `command`, `cwd` and `stop_hook_active` from stdin JSON with `sed`/`grep`, not `jq`
  (`plugins/foundry/hooks/guard-pr-create.sh`, `plugins/foundry/hooks/auto-format.sh`,
  `plugins/foundry/hooks/habit-hooks-guard.sh`). `toolcall.mjs` reads `tool_uses[].tool_name`
  from the Stop payload (`plugins/foundry/scripts/jev/toolcall.mjs#toolNames`).
  `auto-format.sh` emits `hookSpecificOutput.additionalContext` JSON when no Prettier
  config exists (`plugins/foundry/hooks/auto-format.sh`).
- **Jev request and answer shapes** - questions of type `noul`, `score` and `choice`;
  answers carry `noul`, `score`, `choice`, `confidence`
  (`plugins/foundry/scripts/jev/route.mjs#reviewQuestions`,
  `plugins/foundry/scripts/jev/route.mjs#routeReview`). `review.mjs` prints
  `{file, review, lens, reason}` per file, plus `security` when Jev routed it
  (`plugins/foundry/scripts/jev/review.mjs#routeFiles`); `precheck.mjs` prints
  `{proceed, probability, reason}` (`plugins/foundry/scripts/jev/precheck.mjs#verdict`).
